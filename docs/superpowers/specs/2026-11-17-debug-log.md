# Debug log that can be sent as a file

Status: approved by the owner in conversation, 2026-11-17 ("ok awesome, lets ship a release and ill load it on the rp6 and test").

## Why

Device tests are reported with screenshots of chat and Settings > Errors. They
show the error but not what led up to it, and a long test does not fit in
screenshots. The owner wants to test everything in one go and send one file.

An addon cannot write a file of its own. The game writes each addon's saved
settings to disk at logout and at `/reload`; SoulDex's probe already sends its
log that way (`SoulDexProbeLog`). This does the same inside Pocket Essentials.

## What it does

- A "Debug log" switch on Settings > Errors, off by default. While it is on,
  the addon keeps a timestamped line for each thing it does or decides.
- The switch is for anyone: a player who hits a problem turns it on, plays
  until it happens again, and sends the file. It stays as it was left across
  logins until it is switched off again.
- `/pe debug on` and `/pe debug off` do the same from chat, for when the
  settings window itself is the thing that is broken.
- The lines live in the saved settings (`PocketEssentialsDB.debug`), so they
  end up in
  `World of Warcraft/_forever_/WTF/Account/<account>/SavedVariables/PocketEssentials.lua`.
- Next to the switch: how many lines are held, a "Save log now" button (a
  reload, straight from the tap, as the existing "Reload UI" button does) and
  a "Clear log" button.
- `scripts/read-log.sh <file>` prints the log and the Errors page as plain
  text, one block per play session.

## Size

- 3,000 lines, each cut at 200 characters (10,000 before 0.15.0). Full, that
  is a file of about 0.3 to 0.6 MB and about the same in memory. A saved log
  longer than that keeps its newest 3,000 lines, in order; it is not emptied.
- When full, the oldest lines are replaced (a ring: no shifting of the whole
  list, so a full log costs the same per line as an empty one).
- The game loads the saved file at every login whether the switch is on or
  off, so a full log costs that memory until "Clear log" is tapped. The line
  count beside the switch is there to make that visible. Switching the log off
  keeps the lines; only "Clear log" removes them.

## What is written

Each session starts with a header: addon version, game build, which features
are on, Gamepad UI on or off, screen size and UI scale.

One line per decision, never per frame:

| Area | Lines |
|---|---|
| Core | loaded; feature switched on / off / failed to start; every error and every blocked action (the same text as the Errors page); fight started / ended; work held back for after a fight and when it ran |
| Sell junk | vendor opened; how many grey items were found; each sale tried (bag, slot, item number); the first-sale check; why selling stopped; the money line |
| Repair | vendor can repair or not; cost; repaired, refused or not enough money |
| Chat buttons | picker opened; which kind of target was tapped (Say, Party, a channel number, "whisper"); chat box opened or not, and why not |
| One big bag | combined or not and why; size applied or held for after a fight; Sort pressed |
| Quest data | QuestieDB found or not; each rebuild as one line (quests in the log, quests rebuilt, icons made, time taken) |
| Quest icons | world map opened / closed with the number of icons drawn; minimap icons started / stopped and why; a position retry |
| Quest arrow | each change of state (pointing at a quest, text only, hidden) and why; not the distance or the turning |
| Layout | each button pressed and what the game answered |

Rules for every line:

- No names of players and no chat text. A whisper target is written as
  "whisper".
- A value the game hides is written as `<secret>`; it is never read.
- Quests and items are written by number.

## Cost while off

One check of one flag per place that would log. No text is built, nothing is
stored. `PE.debugOn` is read before the line's text is put together.

## Not doing

- No chat-log file (`/chatlog`): it would fill the chat window with these
  lines.
- No sending over the network: addons cannot.
- No log of every frame or every update of the arrow or minimap.

## Parts

1. `Core.lua`: `PE:Debug(key, text)`, the ring in the saved settings, the
   session header, lines for load, switches, errors, blocks and fights.
2. `Settings.lua`: the switch, the count and the two buttons on the Errors
   page.
3. One pass over each feature file adding its lines from the table above.
4. `scripts/read-log.sh` with `scripts/read-log.lua` (LuaJIT; the saved file is
   loaded with no access to files or the system).
5. Tests: the ring (cap, order after wrapping, cut at 200 characters, clear),
   nothing stored while off, no player name in a whisper line, and one vendor
   visit producing the expected lines.

## Version

Goes into 0.0.7, which has not been tested or released, so that the next
device test is the first one that comes back as a file.

## Device test

1. Settings > Errors: turn "Debug log" on.
2. Play through every feature: a vendor with grey items, a repair, the chat
   buttons in and out of a fight, the bag and its Sort tab, quest icons and the
   arrow, a loading screen.
3. Tap "Save log now".
4. Send `PocketEssentials.lua` from the SavedVariables folder.
