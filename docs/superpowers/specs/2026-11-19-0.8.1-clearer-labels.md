# Clearer labels (0.8.1)

From the owner after installing 0.8.0 (2026-11-19): "im really happy so far
... everything else seems pretty smooth so far". Four points. Items 1 to 3
were agreed in chat on 2026-11-19 (the chat name was picked from three
offered: "Chat from round button"). Item 4 is a device test only, no code.

## 1. Hide Blue Quest Haze and Quest Icon Key side by side

In the Quest icons options the toggle and the button that opens the key
page are on one line, toggle first, the button to its right. When the
window is too narrow for both they wrap onto two lines, as toggles already
do.

Rule (Settings list drawer, so the setup guide changes the same way):
toggles and action buttons that follow each other share one line. A run
made of one action button alone is drawn exactly as today (one wide
button, at least 4 button heights wide). Quest arrow's "Move the arrow" is
followed by a choices row, so it does not change.

## 2. The new names, exactly

- The toggle: `Hide Blue Quest Haze`. On screen it reads
  `Hide Blue Quest Haze: On` / `Hide Blue Quest Haze: Off`.
- The button: `Quest Icon Key`.
- The key page's title: `Pocket Essentials - Quest Icon Key`.
- `/qd haze` reports the toggle as "Hide Blue Quest Haze".

Saved key `hideHaze` and its values do not change.

## 3. "Big chat buttons" becomes "Chat from round button"

- The switch: `Chat from round button`.
- The line under it: `Tap the round button to choose who to talk to: Say,
  Party, Guild or someone who whispered you.`
- "Chat text size" stays under it, shown whether the switch is on or off.
- Every other place that names the feature uses the new name: the setup
  guide's round button screen, the Errors page's list of features that
  were on (it reads the label), the TOC notes, README, PRD, CurseForge text.

The module key `chat` and its saved data do not change.

## 4. Menu background: find out why first

With Menu background on, the quest log's small quest menu (Track, Focus,
Share, Abandon) still has no background on the device. No code change in
this round. The device steps ask the owner to switch the debug log on,
open that menu once, and send the saved file. The `menuBg` lines in it
already say whether the game's menu announcements were heard, whether the
quest hook ran, whether a menu was found and whether a panel was shown.
The next round fixes it or removes the feature, from that log.

Saved settings, every other label, every other feature.
