# 0.15.0: polish before the first public post

Status: approved by the owner's instruction of 2026-11-24 ("without asking questions, apply
polish to this addon suite, ironing out bugs and refining the existing features ... I want to
make a Reddit post today"). Built while the owner is away, as an autonomous batch
(spec, subagents, review, GitHub pre-release with both zips). Rulings made without the owner
are listed at the end and copied into `docs/DECISIONS.md`.

Source: a read-only audit of every file by five reviewers on 2026-11-24 (core and helpers;
settings and guide; quests; bags, vendor and chat; controller layout). Only confirmed bugs and
small, safe refinements of what exists are in. No new features, apart from the Spell panel size
row the owner already asked for (`2026-11-24-controller-layout-0.15.0-panel-size.md`, corrected
here). No new game calls except `OnCooldownDone` (L2), which is in Blizzard's source for the
forever branch and gets logged in `docs/ARCHITECTURE.md`.

Every feature still starts off. Saved choices carry over.

## A. Core and small helpers (Core, ErrorCatcher, Hub, Move, LootSparkles, MenuBackground)

- A1. Debug log cap 10000 lines down to 3000 (memory and save time). A saved log longer than
  the cap keeps its newest 3000 lines in order; it is never emptied (today `#lines > DEBUG_CAP`
  empties it, which would wipe every player's log on the first login with a lower cap). Tests
  and the debug-log text that say 10,000 follow.
- A2. Combat queue: a job queued twice under one key runs once. Flush clears `fns[key]` before
  running it.
- A3. Catch all errors: the secret check comes before comparing a message with the last one.
- A4. Loot sparkles: switched off in a fight and reloaded before the fight ended, the game's
  setting stayed on for good. OnLoad puts the saved value back (out of combat) when the
  feature is saved off and a saved value is waiting, as Catch all errors already does.
- A5. Loot sparkles card: "Fully restart the game to remove the sparkles" only when the setting
  really is still on after switching off.
- A6. Error wording: "Another addon handles errors first" when the other addon has no name;
  "An error from a macro or script was caught." and "An error was caught." for those sources.
- A7. Move on screen opened from the settings brings the settings back when it closes (as it
  already does for the setup guide).
- A8. Wording: "See Settings > Errors." everywhere; Debug log "kept until you empty them";
  Loot sparkles help text matches its description.
- A9. Hub: its button scripts and the hold timer go through `PE:Wrap`; the fallback
  ADDON_LOADED listener is dropped once the map hook is on.
- A10. Debug log header lists the features that are running, not the ones saved on.

## C. Quests (QuestData, QuestIcons, QuestArrow)

- C1. QuestData's event handler and rebuild timer go through `PE:Wrap` (house rule; the
  performance recorder can then see them). The debug line reports the work time (summed per
  step) and the number of steps, so the log stops showing waiting time as work.
- C2. Less garbage: AddPin writes spots into scratch arrays; Flush builds tables only for the
  spots it keeps. The QuestieDB harness's pins must be identical before C3 lands.
- C3. Thinning to MAX_PINS works per map, not across all maps, so a zone with few spots keeps
  them (57 quest-and-map cases lost every spot). The harness baseline is updated on purpose.
  As built: an objective keeps about MAX_PINS (300) in all, shared by how many spots each map
  has, and each map keeps at least 30 of its own (or all, if fewer). Total kept spots in the
  harness rose 8% (122638 to 132071); a first version with 300 per map rose 32%.
- C4. Minimap icons come back after leaving a dungeon: PLAYER_ENTERING_WORLD resets the retry
  count.
- C5. Tooltip says "Go to: <name>" for explore spots that carry a name.
- C6. The arrow compares the spot kind too, so a completed quest switches to the turn-in.
- C7. `/qd` uses the settings' words (Tiny, Tracked, "Blue quest haze: hidden").
- C8. Arrow status "Hidden inside dungeons, raids and battlegrounds."; debug log stops writing
  "text only: no quest focused" while the arrow is hidden for resting.
- C9. Option labels that wrap at 720p: "Arrow and text size"; "In cities and inns" with help
  "The \"No quest focused\" line."

## D. Bags, vendor, chat (Bags, Vendor, Chat)

- D1. The whisper list belongs to the character (`PocketEssentialsCharDB`), not the account.
  It is no longer in the shared file players send with the debug log. The old shared list is
  removed at login (each character starts with an empty list once).
- D2. The "Sold N junk items for X" line counts the items and the price of what was sold, not
  the change in money during the visit (buying food, buybacks and hand sales no longer skew
  it, and closing the vendor at once no longer reports too little). N counts items, not stacks.
- D3. The chat picker checks a tapped channel is still there (left a city, left a group) and
  redraws with "That channel is gone." if not.
- D4. The Sort tab hides while the bank is open (it sat over the bank bag's slots).
- D5. Wording: "Chat is set to a whisper to <name>."; "Clear marks" is dimmed when nothing is
  marked; "Sort with a stick click"; Bigger bag "A bigger bag window, with your bags in one row
  at the top."; "Chat picker size"; "All chat windows, even with Chat picker off."

## E. Controller layout and face bars (ControllerLayout, FaceBars)

- E1. Switching the layout on with an old saved layout rebuilds it first, so one reload is
  enough (it took two, with frames over the pictures in between).
- E2. A spell's darkening ends when its cooldown ends (`OnCooldownDone` on our own cooldown
  frame), not at the next cast.
- E3. A slot that gets a different spell re-reads its cooldown.
- E4. When the safety net brings the game's bars back, they return at full size (out of combat).
- E5. Wording: card "Map bottom middle, a spell panel each side (hold LT or RT to swap), chat
  top right."; off line "Needs a reload to switch on or off. Off brings back your own layout.";
  reload reason "Reload to finish the layout change."; the "Template" row is "Rebuild the
  layout" with "Tap Start over again to put every piece back. Changes you made in Edit Mode are
  lost."; fallback prefix "Pocket Essentials' spell pictures are off: "; "Main hand timer",
  "Off hand timer"; no "it is kept" claim about Edit Mode changes.
- E6. **Spell panel size** (the owner's request), from the panel-size spec with these
  corrections:
  - Saved as `panelSize` (80, 90, 100, 110, 120; anything else reads 100). Not `size`: 0.11.x
    left an unused `size` in saved files.
  - A change rewrites the layout out of combat and asks for a reload, like the timer rows
    (pictures, real bars and frames all at the new size after it). In a fight it waits, and the
    card says "Updating the layout after this fight." (today that line shows only for the login
    check).
  - Numbers as in that spec; tests prove no overlaps at every size, including the inner diamond
    against the LB / RB pictures at 120%.

## Left out, and why

- Resetting the chat type after the 12 seconds (`ResetChatTypeToSticky`): not probed.
- Fewer bag layout passes and one re-sync on style change: tiny gain, touches the d-pad route
  that passed the device test.
- A longer first quest rebuild delay at login and clearing QuestieDB's cache: small gains.
- Moving the page number; a wheel opening at the hidden button: no safe fix with existing calls.
- Pet bar cooldowns on the pictures: added to Known.
- `/pe help`: new scope.

## Rulings made without the owner

1. The sell line reports the price of what was sold (was: money gained during the visit).
2. The round button's hold time stays 0.6 s (device-tested); the docs say "hold it a moment".
3. Each character starts with an empty whisper list once, to get names out of the shared file.
4. The Sort tab is hidden at the bank (stick sort still works there).
5. The panel size change asks for a reload instead of redrawing live.
