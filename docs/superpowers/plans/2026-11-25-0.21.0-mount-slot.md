# 0.21.0 Mount slot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One mount square on a "Quick slots" line inside the chat window the PE button opens; a tap mounts or gets off.

**Architecture:** A new file `addons/PocketEssentials/QuickSlots.lua` holds the rules (which mount, what the square says, what a tap does) as functions that take their game calls from a table, so they run offline. `Chat.lua` asks it for one line when it draws its window and adds the square to its own layout and D-pad walk. Nothing listens or ticks.

**Tech Stack:** Lua 5.1 (LuaJIT offline harness), WoW Forever client API (Interface 16001), no libraries.

**Spec:** `docs/superpowers/specs/2026-11-25-0.21.0-mount-slot.md` (read it first; it is the authority).

## Global Constraints

- Verify every game call in `~/.cache/wow-ui-source/forever` and cite file:line in a comment; run `scripts/audit-api.sh` after adding them; log the unverified ones in `docs/ARCHITECTURE.md` with their worst case.
- Never call a Blizzard-written Lua function that writes a field or global; never assign a field on a game frame; touch no Edit Mode frame.

- Comments pass the wording check in `scripts/check.sh` (plain words, as the rest of the code).
- Version 0.21.0 in the TOC with a CHANGELOG entry; `docs/TESTING.md` section 36 in the owner's plain language, modelled on section 35; PRD.md Status line.

- `scripts/check.sh` and `scripts/test.sh` exit 0 before every commit.

## Review Focus

- A character with no mounts, or a client where `C_MountJournal` or one of its functions is missing: the square reads "No mount yet", a tap does nothing, no error.
- A saved mount id the character no longer owns (another character's, or removed): falls back to "First favourite", the saved id is left alone.
- A tap in a fight: no game call at all, the window says "Not in a fight".
- `GetMountInfoByID` answering nil or a secret value for a field: treated as "not usable", never compared or joined.
- Quick slots On with Chat picker Off: nothing is built, the row says it needs Chat picker.

### Task 1: The rules (`QuickSlots.lua`) and their tests

**Files:**
- Create: `addons/PocketEssentials/QuickSlots.lua` (add to the TOC before `Chat.lua`)
- Test: `tests/features/quickslots_test.lua` (wired into `scripts/test.sh` the way `maplook_test.lua` is)

**Interfaces (Produces):**
- `PE.QuickSlots.Mounts(api) -> list of { id=, name=, icon=, favourite=, usable=, active= }`: owned mounts only, in the game's order. `api` is a table with `GetMountIDs`, `GetMountInfoByID`; missing functions give an empty list.
- `PE.QuickSlots.Pick(list, savedId) -> entry or nil, isDefault`: the saved one if owned; else the first usable favourite, else the first favourite, else the first usable, else the first; nil for an empty list.
- `PE.QuickSlots.Next(list, savedId, step) -> id or nil`: steps "First favourite" (nil) → each owned mount → back to nil, both directions.
- `PE.QuickSlots.State(entry, mounted, inCombat) -> { icon=, label=, greyed=, bright=, action= }` with `action` one of `"none"`, `"combat"`, `"summon"`, `"dismiss"`. Labels: mount's name / "Get off" / "No mount yet".
- `PE.QuickSlots:Line() -> state, entry` (reads the real game through its own api table) and `PE.QuickSlots:Tap() -> action` (calls `C_MountJournal.SummonByID(id)` or `C_MountJournal.Dismiss()` inside `PE:Safe`; `"combat"` and `"none"` call nothing).
- `PE.QuickSlots:MountLabel()` and `PE.QuickSlots:StepMount(step)` for the settings row.
