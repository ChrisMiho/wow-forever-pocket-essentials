# 0.8.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Move buttons replace the position presets.
- Bags are split into Bag window and Bag sorter.
- The round button gets colour themes.
- Merge reads as a distance.
- The setup guide gets a touch question and starts the d-pad on Start.
- A slim scroll bar replaces Up and Down.

**Architecture:**
- **Settings drawer:** each change stays inside the file that owns it today. The shared drawer (`Settings.lua`) gains a number `suffix`.
- **Scroll area:** `UI.lua` redraws the scroll area's paging column as a scroll bar. It keeps `area.upButton` and `area.downButton` as the two arrow tabs, so the d-pad lists in Settings, Setup and Chat keep working.
- **Bags:** `Bags.lua` registers a second module, `bagWindow`, over the same engine.

**Tech Stack:** Lua 5.1 (LuaJIT tests), interface 16001, no libraries.

**Spec:** `docs/superpowers/specs/2026-11-18-0.8.0-design.md`

## Global Constraints

- **Code rules:** handlers go through `PE:Safe` / `PE:Wrap`. Nothing ticks while its feature is off. No libraries. Any new game call (texture path, API) is verified in Gethe/wow-ui-source branch `forever`, or logged in `docs/ARCHITECTURE.md`.
- **Labels:** use the exact labels in the spec: "Move the arrow", "Move the round button", "Move on screen", "Bag window", "Sort button", "Sort stick", "Button colour", "Gold", "Horde", "Alliance", "Merge icons closer than", "of map", "Do you use the touch screen?", "Touch screen".
- **Saved data:** existing saved values keep their meaning. New keys: `ui.hubColor`, `ui.touch`, and the `bagWindow` options and enabled state.
- **Version:** 0.8.0 in the TOC and the CHANGELOG together.
- **Tests:** `scripts/check.sh` and `scripts/test.sh` pass after every task.

## Review Focus

- **Old saves:**
  - an old save with `position = "left"` and a Move offset: the arrow stays exactly where it was;
  - Reset puts it at Top with no offset.
- **Bags migration:** an old save with Bag sorter on, `size = "xlarge"` and `iconRow = true`. After loading 0.8.0, Bag window is on with xlarge and one row; reloading again changes nothing.
- **Bag window alone:** no Sort tab, no stick binding, and no d-pad route.
- **Touch off:** with `ui.touch = false` and a long settings list, no scroll bar shows. The d-pad still reaches the last button and scrolls to it.
- **Scroll bar marker:** with content just taller than the view, the marker is tall and its place is right at both ends. A tap on the track pages the right way.

### Task 1: Scroll bar and the touch setting

**Files:**
- Modify: `UI.lua` (`CreateScrollArea`, `AreaMethods:Layout`, `ScrollTo`), and `Core.lua` (`ui.touch` default nil, plus a getter `PE:UsesTouch() -> bool`, which is `ui.touch ~= false`).
- Modify: `Settings.lua` `CoreChoices`, adding the toggle "Touch screen: Yes / No".
- Modify: `Settings.lua`, `Setup.lua` and `Chat.lua`, which put `area.upButton` and `area.downButton` in the navList only when they are shown.
- Tests: `tests/features/ui_test.lua`.

**Produces:**
- `PE:UsesTouch()`.
- The scroll area hides its bar when `not PE:UsesTouch()`, and `Layout` reads it every time.
- `area.track` and `area.thumb` frames.

- [ ] **Tests:**
  - the bar shows only for a list that does not fit and with touch on;
  - the marker's height is `viewHeight / contentHeight` of the track (at least `M.button * 0.5`);
  - the marker is at the track top at offset 0 and at its bottom at the full range;
  - a tap on the track below the marker calls PageDown, and above it PageUp;
  - the arrows dim at the ends;
  - with `ui.touch = false` the bar is hidden, the list is full width, and the d-pad reaches the last settings button;
  - the toggle in the settings flips `ui.touch` and redraws.
- [ ] Implement, then run check and test, then commit.
