# 0.9.0 UI Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the in-game UI match the "Proposed" mockups.

**Architecture:**
- New shared widgets live in UI.lua: switch, segmented choice, number, card, and an option row with a help line.
- Settings.lua draws tabbed pages from each feature's `options` list. Setup.lua draws its cards through the same list drawer.
- Each feature file keeps its own names, lines and option lists, using the interface below.
- Quest arrow, Chat, Bags and Move change only their own files.

**Tech Stack:** Lua 5.1 (WoW Forever, interface 16001). No libraries. LuaJIT offline tests (`scripts/check.sh`, `scripts/test.sh`).

**Spec:** `docs/superpowers/specs/2026-11-20-0.9.0-ui-redesign.md`, with the visual source `docs/ui-review/mockup-0.8.1.html` (its PROPOSED section).

## Global Constraints
- Interface 16001, modern API, no libraries in the addon.
- Every event handler and callback goes through `PE:Safe` or `PE:Wrap`.
- Nothing ticks while its feature is off. Features default off.
- Every new game API must be verified on the forever branch (IsResting and PLAYER_UPDATE_RESTING already are). Run `scripts/audit-api.sh` after adding a game call.
- Sizes are 720p units through `UI:Px` / `UI:Metrics()`. Never write raw pixels except where the spec says raw.
- The code comments must pass the `scripts/check.sh` wording check.
- `scripts/check.sh` and `scripts/test.sh` must pass before each task is done.

## Option-row interface (every task relies on this)
A feature's `options` entries keep today's shapes, with these additions:
- `help = "text"`: a grey line under the row name.
- `number = { ..., step = n }`: the step of the − and + ends. The default is 1.
- Action rows: `{ label = "Row name", button = "Button text", action = fn }`. Without `button`, the text is "Open".
- Choice rows are drawn as segmented controls, whether `toggle` is set or not.
- `always = true`: shown while the feature is off (as today).
- Setup screens choose rows by option `key`: Setup.lua holds `only` lists per screen.

## Review Focus
1. Large button size: the 8 tabs must still fit in the Settings content height, and a long row name must wrap without overlapping its control.
2. Old saved values: `questArrow.size` (small/normal/large) migrates once to `scale`. A stray `iconRow = false` must not undo the top-row icons while Bigger bag is on.
3. The d-pad: every segment, switch, number end and tab is reachable. Right/Left cross between the tab column and the page.
4. Off features: Move on screen still lists all three pieces, dimmed. The Chat tab still shows Chat text size with Chat picker off.
5. Resting: the arrow hides only in the "No quest focused" state and only while `restHide` is on. `PLAYER_UPDATE_RESTING` is registered only while the arrow is on.
