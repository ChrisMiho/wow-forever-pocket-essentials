# 0.20.0 After The First Sitting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Whole names on the slim bars, the owner's arrangement as the built-in one without anyone's screen moving twice, the Part rows gone, and the spell wheel buttons movable without a second switch.

**Architecture:** Four independent changes on top of 0.19.0. Names live in `SlimBars.lua`. The arrangement is one table of amounts inside `Plan` added where the session's offsets are added, plus a one-time migration of saved offsets. The Part rows and the wheel switch are removals in `ControllerLayout.lua` and `Arrange.lua`.

**Tech Stack:** Lua 5.1 (LuaJIT offline), the WoW "Forever" client API (Interface 16001), the repo's offline harness under `tests/`.

**Spec:** `docs/superpowers/specs/2026-11-25-0.20.0-after-first-sitting.md`

## Global Constraints

- Blizzard's source: `~/.cache/wow-ui-source/forever` at `c01a87b`. Verify every new game call there and cite file and line in a comment beside it.
- No call into a function Blizzard wrote in Lua that writes a field or a global; no field assigned on a game frame. `tests/taint/audit.lua` passes with no new kept call.
- `ControllerLayout.lua` is near Lua's limit of 200 top-level locals: add none; removals are welcome.
- Handlers through `PE:Safe` / `PE:Wrap`; game changes out of a fight through `PE:RunOutOfCombat`; game calls through `pcall`.
- Plain language in every string the player sees; comments pass `scripts/check.sh`.
- Stage files by name; never `git stash`, `git add -A` or reset. Do not push.
- `scripts/check.sh` and `scripts/test.sh` exit 0 before every commit. Existing tests change only where this plan removes the thing they test (the Part rows, the wheel switch, the hook) or where a built-in spot moves by a table amount; say which in the commit message.

## Review Focus

- A character whose saved live offsets differ from the owner's (for example player bar -10,0): after the migration every rectangle is where it was, to the unit.
- Two characters on one account: the layout's Edit Mode offsets migrate once (first login), each character's live offsets at that character's own first login; the second character must not migrate the layout's again.
- A saved file from 0.18.0 with Part rows Off and Arrange Off: every part is placed, the new built-in spots are used, one reload prompt at most.
- A saved wheel offset with the old switch Off: it was not applied before; it must not suddenly apply now (clear it), while one saved with the switch On keeps applying.
- A unit whose `UnitName` second answer is a realm (another realm's player), an empty string, or hidden in a fight: never shown, never joined.
