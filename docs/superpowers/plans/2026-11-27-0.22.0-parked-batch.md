# 0.22.0 Parked Batch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the eleven parked items of the 0.22.0 spec, each behind its own row (Off by default) under a "0.22.0" header on the Controller tab, each with its own debug-log lines.

**Architecture:** One new small file, `Batch.lua`, owns the list of batch rows, the "is this row on" question and the login log line; every other file asks it and changes nothing while its row is Off. Layout items go through `PE.LayoutPlan` (`Plan.Pieces`, `Plan.Rects`, `Plan.ARRANGE`) so the game places its own pieces from our Edit Mode layout; nothing touches a game frame directly.

**Tech Stack:** Lua 5.1 as the game runs it, checked offline under LuaJIT with the fake client in `tests/lib/fakeclient.lua`. No libraries.

**Spec:** `docs/superpowers/specs/2026-11-27-0.22.0-parked-batch.md`. Read it first, then `docs/SCREEN-MAP.md` (positions and units) and `docs/11-27-morning/HANDOFF-2026-11-27.md` (source lines found so far). Mockups: https://claude.ai/artifact/B6emNUJNYkzyeQPghzaMAH.

## Global Constraints

- Every batch row defaults to Off. With every row Off, the plan's numbers, the pieces written into the layout, what is drawn and the game calls made are exactly 0.21.0's.
- Nothing ticks, listens or draws while its row is Off.
- Never call a Blizzard-written Lua function that writes a field or a global. Never assign a field on a game frame. Never SetPoint, SetScale, Hide or Show an Edit Mode system frame: the layout is the only way to place one.
- Verify every new game call, event, frame field, enum and CVar in the pinned source at `~/.cache/wow-ui-source/forever` (branch `forever`; only code that loads for game type `camelot` counts) and cite file and line in a comment. What cannot be verified goes into the Unverified table of `docs/ARCHITECTURE.md` with its worst case, and the call is guarded (`type(x) == "function"`, `pcall`).
- Event handlers and callbacks go through `PE:Safe` or `PE:Wrap`.
- Debug lines: `if PE.debugOn then PE:Debug("<module key>", "<text>") end`. A line is at most 200 characters. The texts in this plan are exact.
- `ControllerLayout.lua` is at Lua's limit of 200 top-level locals: add no top-level `local` there. New numbers and functions go on `Plan`, `Snap` or another existing table.
- Comments are plain sentences; `scripts/check.sh` checks their wording. Run it after every edit.
- Git: stage files by name. Never `git add -A`, never stash, never reset. Never touch `.claude/settings.json`. Do not commit the session folders under `docs/` (`docs/11-*`).
- Tests: `scripts/check.sh` (0.1 s), `luajit tests/features/run.lua "$PWD"` (the feature tests alone, fast), `scripts/test.sh` (everything, over two minutes: give it a 10 minute timeout).
- Units: UI units on a 1365.33 by 768 screen. In `Plan`, x counts from the screen's centre and y up from the bottom edge; a `Spot(point, relativePoint, x, y)` is on UIParent.

## Review Focus

1. A character with no surname, or a name longer than fits: the layout name must still be built, never raise, and never exceed 30 letters (Task 11 tests).
2. A client where the Cooldown Manager system or one of its settings is missing from the enums: the timers row must skip those pieces and log it, not raise (Task 8 tests, with the fake enums stripped).
3. Rows turned On in a fight: every layout write must wait until out of combat, as the existing rows do (`PE:RunOutOfCombat`); a test per layout row turns it On with the fake client in combat and checks no layout call was made until combat ends (Tasks 6, 8, 9, 10, 11).
4. "Turn all on" pressed while Controller layout itself is Off: the rows flip, nothing else happens, nothing raises (Task 1 test).
5. A D-pad press in a window with one button, or with buttons that are hidden: the highlight stays, no error (Task 4 tests).

    | key | label | reload |
    |---|---|---|
    | `b22Empty` | Empty slots, clean | false |
    | `b22Arrows` | Menu arrows, always | false |
    | `b22Dpad` | D-pad moves by direction | false |

  - `PE.Batch.SetAll(on)`: sets every key of `ROWS` to 1 or 0 in the options, then calls `Changed` for each key whose value changed.
  - `PE.Batch.Line() -> string`: `"batch: 0.22.0 rows: b22Empty=off b22Arrows=off ..."` in `ROWS` order.
- The options live in the Controller layout's own table (`PE.db.options.ctrlLayout`, `mod.opts` inside `ControllerLayout.lua`). No new saved table.
- One more option, not a batch switch: `b22BarsSide` (0 "Left, by your name", 1 "Right, by the target"), default 0, used by Task 8.
