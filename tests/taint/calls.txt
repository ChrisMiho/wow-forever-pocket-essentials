# Verdicts for tests/taint/audit.lua: one line for each name our code calls (or names in a string)
# that Blizzard also defines as a Lua function somewhere under Interface/AddOns. The match is by
# name only, so each line is a reading of the call sites in that file against Blizzard's source
# (wow-ui-source, branch forever, build 1.60.1.71091; game type camelot, family mainline).
#
#   name<TAB>our file, or * for every file without a line of its own<TAB>verdict<TAB>reason
#
# Verdicts (see the header of audit.lua):
#   ours          the function called under this name is the addon's own
#   engine        a frame's own engine (C) method, a C global or a C_ function; or the name is
#                 only hooked, only read, or only a string or table key, and never called
#   clean         Blizzard's Lua function is really called; it was read and writes no field and no global
#   writes-known  Blizzard's Lua function is really called and it writes the field or global named
#                 in the reason (itself or in a function it calls); printed on every run
#   writes        the same, and not accepted: the check fails
# * is allowed with ours and engine only. A line for one file wins over the * line.
# Sorted by name, then file. Blizzard paths are relative to Interface/AddOns; where only a file
# name is given it is in the folder named earlier on the same line or in Blizzard_SharedXMLBase,
# Blizzard_SharedXML, Blizzard_GamepadActionBars or Blizzard_EditMode/Shared.
#
# Not seen by the check, so not listed here: a Blizzard function reached through a variable or a
# dotted string (ChatFrameUtil.GetActiveWindow and ChatFrameUtil.ResolveChannelName in Chat.lua,
# the probe's Find("ChatFrameUtil.OpenChat") and the like), and the Lua script handlers the game
# runs when an engine method shows, hides or focuses one of its frames.
